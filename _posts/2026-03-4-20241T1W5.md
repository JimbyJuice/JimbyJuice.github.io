## 2. Turnip Commands

### `turnip-add`
Stages files for submission — like `git add`. Tells turnip "I want to submit this file."

```sh
turnip-add extract.sh
turnip-add last.sh
```

### `turnip-submit`
Submits your staged files — like `git commit` + push to the marker.

```sh
turnip-submit
```

### What else do you need to submit?
Any files your script depends on that aren't auto-provided. For example:

- If `extract.sh` uses a helper function in `utils.sh`, you need to `turnip-add utils.sh` too
- If the task says "submit your script and a test file", add both

**Example:**
```sh
turnip-add extract.sh
turnip-add extract_test.sh   # your test file
turnip-submit
```

## 4. `extract.sh` — Extract Archives with the Right Program

Different archive formats need different tools:

| Extension | Command |
|---|---|
| `.tar.gz` / `.tgz` | `tar -xzf` |
| `.tar.bz2` | `tar -xjf` |
| `.tar.xz` | `tar -xJf` |
| `.tar` | `tar -xf` |
| `.gz` | `gunzip` |
| `.bz2` | `bunzip2` |
| `.zip` | `unzip` |
| `.xz` | `unxz` |

```sh
#!/bin/dash

for file in "$@"; do
    case "$file" in
        *.tar.gz|*.tgz)
            tar -xzf "$file"
            ;;
        *.tar.bz2)
            tar -xjf "$file"
            ;;
        *.tar.xz)
            tar -xJf "$file"
            ;;
        *.tar)
            tar -xf "$file"
            ;;
        *.gz)
            gunzip "$file"
            ;;
        *.bz2)
            bunzip2 "$file"
            ;;
        *.zip)
            unzip "$file"
            ;;
        *.xz)
            unxz "$file"
            ;;
        *)
            echo "extract.sh: unknown file type: $file" >&2
            ;;
    esac
done
```

**Key points:**
- `"$@"` loops over all command line arguments
- `case` matches on file extension
- `>&2` sends error messages to stderr (correct practice)
- Always quote `"$file"` to handle filenames with spaces

#!/bin/dash

## 6. `top-and-bottom` — Shell Function

```sh
#!/bin/dash

top-and-bottom() {
    file="$1"
    first=$(head -1 "$file")
    last=$(tail -1 "$file")

    echo "================="
    echo "$file"
    echo "-----------------"
    echo "$first"
    echo "$last"
    echo "================="
}
```

**Usage:**
```sh
. top-and-bottom.sh                            # source the file to load the function
top-and-bottom /usr/share/dict/british-english-insane
```

**Key points:**
- `. file.sh` (dot space) sources the file — loads the function into your current shell
- `head -1` gets the first line, `tail -1` gets the last line

## 7. `print_message` — Optional Exit Status Function

The trick here is detecting whether an exit status was passed. If `$1` is a number, treat it as exit status; otherwise treat everything as the message.

```sh
print_message() {
    # Check if first argument is a number
    case "$1" in
        ''|*[!0-9]*)
            # Not a number — print warning
            echo "warning: $*"
            ;;
        *)
            # Is a number — print error and exit
            status="$1"
            shift
            echo "error: $*"
            exit "$status"
            ;;
    esac
}
```

**Usage:**
```sh
print_message "something went wrong"       # warning: something went wrong
print_message 1 "file not found"           # error: file not found  (then exits with code 1)
```

**Key points:**
- `case "$1" in ''|*[!0-9]*)` — matches if `$1` is empty or contains a non-digit
- `shift` removes `$1` from the argument list, so `$*` now contains just the message
- `exit "$status"` exits the whole script with the given code

## 8. Git — Create Repo, Add Labs, Push to CSE GitLab

```sh
# Create the repo
mkdir cs2041-Labs
cd cs2041-Labs
git init

# Copy in your lab work
cp -r ~/path/to/week01 .
cp -r ~/path/to/week02 .

# Stage and commit
git add -A
git commit -m "Add week01 and week02 lab work"

# Add CSE gitlab as remote and push
git remote add origin https://gitlab.cse.unsw.edu.au/YOUR_ZID/cs2041-Labs.git
git push -u origin main
```

**Important:** When logging into CSE GitLab, use **"Login with UNSW Single Sign On"** — not the username/password fields.
